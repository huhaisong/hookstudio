## 一、先说结论：三件已经改好的事

### 1. 报错翻成人话（`app/analyze.py` 的 `_http_error`）
横评跑到第 13 个模型时，百炼突然所有模型都报
`400 {"type":"Arrearage","code":"Arrearage"}` —— **账号欠费了**。
原来的界面会把这段英文字典原样甩给你，看不出是欠费、没开通还是 Key 坏了。

现在按关键词认一遍，各给人话 + 下一步动作：

| 接口原话 | 界面现在说 |
|---|---|
| `Arrearage` / `overdue payment` | 百炼账号欠费了，去控制台充值，Key 不用换；想先用着就切 deepseek-v4-pro |
| `token is unusable` | 这个模型的产品没开通，去模型广场申请 |
| `Access denied` / 403 | 没申请这个模型，或业务空间没加它 |
| `invalid_api_key` / 401 | Key 不对或失效 |
| `Throttling` / 429 | 被限流，等一两分钟 |
| 超时（≠连不上） | 等了 N 秒没返回，换模型或缩小任务，**不是网络断了** |

### 2. 设置页「测试连通」（`POST /api/llm-test`）
13 个模型里 4 个失败，每次都要等十几分钟任务跑完才知道原因。现在一个按钮，
拿输入框里**还没保存**的 Key 和模型发一次 30 字请求，几秒出结果：

- 欠费 0.3 秒说清；DeepSeek 0.7 秒返回「接口可用」
- 探针走的是和正式调用**同一条代码路径**（`core.route` + `_endpoint` + 思考开关三档降级），
  所以「探针通过 ≈ 正式能跑」，不是另写一套假测试
- 顺带解决了「填了 Key 直接保存、跑起来才发现是错的」

### 3. 第 2 步参数按素材自动算
套数/最短/最长一直是写死的 3 / 4 / 5。现在按「套数 × 单套 ≈ 素材的八成」算：
新项目第一次进第 2 步自动填一次（只填一次，不覆盖你手改的值），旁边留「按素材推荐」按钮。

**同一部剧、同一个 deepseek-v4-pro，做了一次对照**：

| 参数 | 结果 |
|---|---|
| 3 套 × 10.5 分钟（超出素材 45%） | 三套重合 **100%** |
| 2 套 × 5.5-6.5 分钟（素材的 83%） | 两套 366s / 374s，重合 **41%** |

—— 那 100% 不是模型不会剪，是要的比素材多。

## 三、我的建议（按「不做会疼」排序）

### 1. 百炼充点钱，这是唯一阻塞
不用多，按实测一次排 3 套结构约 2-4 分钱算，¥50 够跑十几次。
不充也能用，但只能走 DeepSeek，等于放弃「几套不一样」这个核心卖点。

### 2. 默认模型定谁：我建议保持 qwen3.5-plus，不换成 GLM-5.2
GLM-5.2 实测最快（59 秒）时长最准，但**只有 1 次数据**；复核跑到一半账号欠费了，
所以「它每次都这么快」这件事没被验证。qwen3.5-plus 慢 3.5 倍但不用开通、是阿里自家模型、最稳。
折中做法：默认值不动，设置页里已经标了实测数据，你哪天确认 GLM-5.2 稳定，改一行 `DEFAULT_CONFIG` 就行。

### 3. 第 2 步和第 4 步分开配模型
现在两处共用一个 `llm_model`。但这两个任务要的东西相反：
- 第 2 步要**快、套间不重复**（GLM-5.2 最优）
- 第 4 步要**写得细、一次过**（qwen3.8-max 最优）

加一个 `shots_model` 字段、`analyze._call(model=...)` 传参就能分家。改动约 40 行，我没动是因为
百炼欠费状态下没法端到端验一遍，不想留一个没测过的叉路。

### 4. 结构生成要能「中途放弃」
现在是单次长请求（默认最多等 600 秒），step-5 那轮等了 **34 分钟**才超时，
这 34 分钟里界面除了进度条什么都不给，也没法取消。三个选项，成本从低到高：
- 便宜：超时时间按模型分档（推理型给 300 秒就够，反正是排队）
- 中等：请求改成流式（`stream: true`），把「已经收到多少字」显示出来
- 贵：拆成「先出 1 套 → 确认 → 再出剩下的」，能中途停，但要改提示词和落库结构

### 5. 重合度这件事，还差一个「自动降档」
现在只提示不拦。真正的解法是**算完发现要的比素材多，就自动把套数降一档再问一次**，
而不是让模型硬交三套几乎一样的。我已经把「八成」这条规则写进前端和 `plan_note`，
但没人拿它去改请求参数——因为自动改用户填的数字容易让人困惑。
建议做成「点生成时如果超预算，弹一句：素材只够 2 套，要按 2 套跑吗？」

### 6. Kimi / MiniMax-M3 值得再试一次
四个失败里，Kimi 两个是「产品没开通 / 额度不够」，MiniMax-M3 是「账号没授权」。
这三个不是模型不行，是没通。你在百炼上开通后，点一次「测试连通」就知道通没通，
不用再跑十几分钟。STEP-5 不用再试了，34 分钟没出结果，是真慢。

### 7. 打包前记得两件事
- 清空 `dist\HookStudio\data`（现在里面可能有测试项目的残留）
- `prompts/` 里 `funnel.txt`、`plans.txt`、`hooks.txt`、`shots.txt` 改过的话，
  打包脚本要带上最新版，`build.bat` 的 robocopy 规则别漏
