## 2026-11-14 · 00:00 根因修复 + 队列按钮改版

### 定时 00:00 攻坚（根因实锤 + 修复）
- **根因**（探针 `data/diag/sched_steps5~7` + 组件源码实锤）：平台日期组件是 Vue 的
  `mp-date-picker`。点 hour/minute 的 li 只走 `handleTimeChange`——**它只改组件内部
  `pick`，不 emit `input`**，父组件（`post-time-wrap`）的 `data.time` 停在点日期那一刻
  的默认值。所以框里显示 20:00（显示层跟着 pick 走）、平台收到的却是旧值（验收时
  为 00:00）。
- **修法**（`wxpost.set_schedule`）：点完时分后，校验 `pick === 目标时间戳`，
  再调组件自己的 `handleTimeSelect()`（真正对外 emit input/change 的提交入口）；
  随后**核对父组件 `data.time` 必须逐字等于目标**（唯一可信的提交值），再加原有
  的框上文本读回，三道判据，对不上就 PostError 停手，绝不带错时间往下走。
- **复验**：探针里生产函数设 2026-11-15 20:30，`before` 即为目标值（提交已在

**判登录不能只看刚加载的 URL**：SPA 可能过几秒才弹二维码。最终判据 = `wait_for_url` + 等 2.5 秒 + 查 `qrconnect` 帧，另回传窗口可见文字作诊断（不拿文案当判据）。号正忙时 25 秒等不到 cookie 就如实说「等它跑完再点」，绝不为开窗口去打断后台任务。

### 关键技术结论（别再走回头路）

1. **Chrome Local Network Access**：公网页面 `channels.weixin.qq.com` 取 `127.0.0.1`
   会被硬拦（`Permission was denied ... 'loopback' address space`）。加 CORS 预检头
   `Access-Control-Allow-Private-Network: true` 仍不够；**必须**在自动化浏览器的启动参数里
   加 `--disable-features=LocalNetworkAccessChecks`。只影响我们自己拉起的实例。
2. **表单帧**：直接 `goto` 发表页会停在「最近视频」弹层 + JS 引导页，
   `micro/content/post/create` 那一帧常年是引导页。**必须先真实点「发表视频」**
   （`wxpub.open_post_form`）再按内容选帧（`wxpub.form_frame`，score≥3 且有 file input）。
3. **大文件**：`frame.locator() / set_input_files / query_selector` 在这个跨域 iframe 里
   全部数不到元素（实测 `locator count=0` 但 `document.querySelector` 拿得到）。
   走「页面 `fetch(本机地址)` → blob → File → DataTransfer → input.files」。
4. **`_mouse_click` 按文字找元素必须只挑可见的**：页面上同时挂着 6 个「确认」
   （2 可见 / 4 隐藏），取第一个会点到 `width=0` 的那个，静默无反应。
   共用 `_PICK_JS`（可见优先、取最深）；容器内按文字点用 `_pick_cell`。
5. **定时发表时间不是 input**：`请选择发表时间` 是 readonly，原生 setter 赋值会被
   组件状态覆盖（填 `2026-11-14 20:00` 读回 `2026-11-13 23:00`）。真实路径是
   radio → 展开日历 → 翻月（左箭头 `display:none`，只能往后）→ 点日期 →
   展开时分下拉 → 在 `ol...__hour` / `ol...__minute` 里真实点 → 读回逐字核对。
6. **位置必须主动清**：页面每次打开发表页都沿用上次城市（实测「邵阳市」）。
   用户没填位置 ≠ 不带位置，要点候选里的「不显示位置」，否则整批标错城市。
7. **话题不能粘在标题后面**：描述第一行会被平台当标题，`标题#短剧` 会污染标题。
   把话题并进描述、用换行分隔一次写入。
8. **封面成功判据**：「封面已更新」是 toast，可能挂在主 frame 或一闪而过；
   可靠信号是**弹层关闭**（可见的「确认」按钮消失）。

## 2. 目标 / 非目标

### 目标
- 一次排 1~15 条，跨多个视频号，交互相对于逐条手动操作要快一个数量级
- 定时交给平台自带能力，**上传完即可关机**（发布由微信服务器执行）
- 每条状态可追溯：传到哪、成没成、失败原因、人工接手没有

### 非目标
- 不做「无人值守 7×24」：本机必须在上传那一刻开机联网
- 不做发布后的数据回收（播放量/点赞），那是另一个功能
- 不做素材库/选题库/演员筛选（小V猫那套），我们只从本项目成片 + 本地文件取
- 不做图文、直播、合集创建

## 3. 平台硬约束（实现时必须校验，不能靠用户自觉）

| 约束 | 值 | 处理 |
|---|---|---|
| 定时最早 | 约 5~10 分钟后（以界面提示为准） | 首条时间 < now+10min 直接拦 |
| 定时最晚 | **最多提前 7 天（168h）** | 末条超出则拒绝排期，提示「拆成两批」 |
| 定时发布是否走审核 | **走**，审核不过即失败 | 必须回读「待发布」列表，不能只看点击成功 |
| 单条时长 | 约 18 分钟 | 本地预检，超限拦住不上传 |
| 单条大小 | 约 2GB 量级 | 同上 |
| 带货视频日上限 | <10w 粉 5 条/天；≥10w 粉 10 条/天 | 超限给黄色警告，不硬拦（无法准确判断账号资质） |
| 短标题 | ≤16 字 | 超长前端截断 |

> 上线前用真实账号实测三条边界（最早/最晚/日上限），把实测值写进 `wxchannel.LIMITS`，代码只认这个常量。

## 4. 术语

| 词 | 含义 |
|---|---|
| 账号（account） | 一个视频号 + 一套独立浏览器 profile + 一份登录态 |
| 作业（job） | 一条视频的一次发布，是队列的最小单位 |
| 批次（batch） | 一次排期生成的一组作业，共享首条时间与间隔 |
| 计划时间（plan_at） | 该作业在**平台侧**的定时发布时间 |
| 上传中（uploading） | 正在传文件 + 后台转码 |
| 已托管（scheduled） | 已在后台设好定时，等平台到点发（**不等于已发出**） |
| 人工接手（manual） | 自动化失败，已降级 B，等用户手动发 |

## 5. 用户流程

```
① 打开「发布计划」抽屉
② 账号区：首次点「登录」→ 弹出可见浏览器 → 用户扫码 → 检测到已登录 → 状态变绿
③ 添加：勾选本项目成片（自动带标题/集数/时长/大小）或拖入本地文件
④ 模板：话题 / 合集 / 原创声明 / 可见范围 / 封面取帧 —— 填一次全批套用
⑤ 排期：选首条时间 + 间隔 → 实时显示「最后一条 11-16 14:00，共 8 条」+ 越界告警
⑥ 点「开始排队」→ 队列逐条执行
⑦ 界面按状态实时刷新；失败的条目变红并降级为人工
⑧ 平台到点自动发；用户在「已托管」列表能看到每条的去向
```

**关键交互原则**：用户只在 ②③④⑤ 做决策，⑥ 之后不再需要盯着。但要能一眼看出「卡在哪一条」。

## 6. 数据模型

### 6.1 账号（全局，跨项目）

`data/publish_accounts.json`

```json
{
  "v": 1,
  "accounts": [
    {
      "id": "acc_a1b2c3",
      "name": "大彬的绳生",
      "profile_dir": "data/publish_profiles/acc_a1b2c3",
      "state": "online",
      "last_check": "2026-11-12T23:50:00",
      "last_ok": "2026-11-12T23:50:00",
      "note": ""
    }
  ]
}
```

- `state`: `online` | `expired` | `unknown` | `busy`
- `profile_dir` 存在但目录丢失 → 置 `expired`
- 账号属于**用户**不属于项目：换项目不用重登；换电脑要重登（登录态不跟着走）

### 6.2 项目侧配置

`project.json` 顶层新增 `publish` 字段（走 `core.save_merge(p, ["publish"])`）

```json
{
  "publish": {
    "v": 2,
    "template": {
      "topics": ["短剧", "反转"],
      "collection": "",
      "original": false,
      "visibility": "public",
      "desc_tail": "",
      "location": "",
      "activity": "",
      "link": "",
      "declare": ""
    },
    "batch": {
      "id": "bat_x1",
      "first_at": "2026-11-13T12:00:00",
      "interval_min": 120,
      "account_id": "acc_a1b2c3",
      "created_at": "2026-11-12T23:55:00"
    },
    "jobs": [
      {
        "id": "job_7f3a",
        "file": "D:/out/第1集-逃婚.mp4",
        "src": "set:3",
        "hash": "sha1:...",
        "title": "",
        "title_src": "template",
        "short_title": "",
        "topics": [],
        "cover_ts": 1.2,
        "collection": "",
        "location": "",
        "activity": "",
        "link": "",
        "original": false,
        "declare": "",
        "account_id": "acc_a1b2c3",
        "plan_at": "2026-11-13T12:00:00",
        "status": "queued",
        "attempts": 0,
        "error": "",
        "remote_hint": "",
        "verified_at": "",
        "created_at": "2026-11-12T23:55:00",
        "done_at": ""
      }
    ]
  }
}
```

字段说明：
- `src`：`set:<index>` 表示来自本项目成品（`p.sets[]`），`file` 表示外部文件
- 界面能选哪些成片由后端 `publisher.pickable_sets()` 统一给（跟着 `GET .../publish` 的 `sets` 走），**两道过滤**：只认当前结构版本 `gen`（和主界面 `renderSets` 同一口径，旧 gen 的文件还在硬盘上，混进来会让人以为这套已经出好了，发出去还是上一版结构）、没有 `output` 的套不列（点了只会拿到一句报错）。前端**不许**自己读 `proj.sets` 拼列表，`add_jobs` 也用同一个函数取文件，避免「界面能勾、后端不认」
- 单集钩子模式（`plans[0].mode == "hook"`）下一套就是一集，标签写「第 N 集」，不写「第 N 套」
- `hash`：文件内容 sha1 前 16 位，用于**重复发布保护**
- `remote_hint`：回读列表时抓到的标题/时间片段，用于人工核对（不存远端 id，平台不给稳定 id）
- `topics` 为空则继承 `template.topics`
- `batch.account_id` 是**单值**（对应决策 5：多个视频发同一个号）。2026-11-14 起取消锁号：提交后的作业账号随任务走不允许单独改（改状态只在「已提交」里以取消的形式做），切号只影响后续批次
- `file` 为绝对路径 → 启动/开始前必须校验存在性，缺失标 `failed`（原因「视频文件不见了，可能被移动或清理」），不静默跳过

### 6.2.1 发布字段（v2，2026-11-13 对齐小V猫）

口径：**平台发布页上有几项，这里就有几项**，一项都不留给"用户自己去后台补"。

| 键 | 中文 | 校验 | 默认 |
|---|---|---|---|
| `title` | 标题 | ≤100 字，可空（空则用剧名-集号） | 自动 |
| `short_title` | 短标题 | 0 或 6–16 字 | 空 |
| `topics` | 话题 | ≤8 个、每个 ≤20 字，存盘不带 `#` | 自动生成 |
| `cover_ts` | 封面取帧 | 取第几秒，≥0 的浮点；设了封面图片后失效 | 0（首帧） |
| `cover_file` | 封面图片 | 只认 `publish_cover/xxx.png` 相对名（后端复制），空＝继承整批默认 | 空 |
| `collection` | 合集 | ≤30 字，**只能填号里已建好的** | 空 |
| `location` | 位置 | ≤40 字 | **空**（自动定位容易定错城市） |
| `activity` | 活动 | ≤30 字 | 空 |
| `link` | 扩展链接 | 必须 `http(s)://`，≤500 | 空 |
| `original` | 声明原创 | bool | **false**（号没权限会被驳回） |
| `declare` | 视频声明 | `""` / `self`（自制）/ `ai`（含 AI 生成） | `""` |

三条硬规矩：

1. **校验只在后端**（`publisher.norm_field`），前端原样传值。前端顺手截断一次、后端再判一次，两处早晚分叉（同「列出来/点下去同源」那条铁律）。
2. **`original` 默认 false，且 v1 的老值一律按 false 读**：v1 那个 `true` 是代码默认值，当时界面根本没地方能改，不是用户的选择。替用户默认勾上原创等于替他做一个有风险的承诺。
3. **整批套用只覆盖「整批一致」的项**（`BATCH_KEYS = collection / location / activity / link / original / declare / topics`）。标题、短标题、封面取帧秒数逐条不同，套同一个值等于把 15 条视频发成 15 个同名作品。**封面图片是例外**：只写 `template.cover_file`，不进 `BATCH_KEYS`、不灌进每条；详见最前面的「封面图片变更」节。
   套用范围只到 `draft / failed / manual`；已经在 `queued` 的不动（用户可能一条条改过）。


### 6.3 运行时状态（不落库，内存）

worker 单线程串行，运行态放 `publisher._RUNTIME`：

```python
{"running": bool, "current_job": str|None, "pct": float,
 "msg": str, "account_id": str|None, "started_at": str}
```

轮询接口 `/api/publish/status` 返回它 + 各项目 queued 计数。

## 7. 状态机

```
draft ──排期──> queued ──worker取──> uploading ──成功──> scheduled
                   │                    │                  │
                   │                    │                  └─到期回读──> published
                   │                    └─失败──> failed ──重试──> queued
                   │                                    └─降级──> manual
                   └─用户取消──> skipped
```

约束：
- `scheduled` 表示「平台已接管」，程序不再管它，只做展示
- `published` 只能靠**回读**确认（到期后 10 分钟内查一次待发布/已发布列表）；查不到不代表失败，标 `unknown` 让用户自己看一眼，**不许假装成功**
- **关机补读**：`scheduled` 且 `plan_at < now` 的作业，程序启动时统一补一次回读。否则用户传完就关机，第二天打开看到一堆「已托管」永远不动
- `failed` 最多自动重试 2 次（间隔 5/15 分钟），再失败自动转 `manual`
- `manual` 是终态，用户点「已发」→ 转 `published`，点「跳过」→ `skipped`
- **pro 到期不打断**：已进 `queued` 的作业继续跑完（否则客户队列跑一半突然停更，比不能新增更糟）；`draft` 状态的拒绝提交并提示升级

### 7.1 删除项目时的队列处置（决策 3：让用户选）

删除项目时若 `publish.jobs` 里还有 `queued/uploading/failed/manual` 的条目，弹窗二选一：

| 选项 | 行为 |
|---|---|
| **取消删除** | 什么都不做，回列表 |
| **仍然删除** | 本地 job 全清，项目目录删除 |

弹窗必须写清两件事（这两句不能省）：
1. 「本项目还有 N 条没发完，删除后**本地记录会消失**」
2. 「**已经设好定时发布的那几条，会照常在视频号到点发出**，需要你到视频号助手手动取消」

> 第 2 句是关键的诚实点：删项目**撤销不了平台侧的定时**。不写这句，客户会以为删了就没事，结果第二天视频照发。

## 8. 排期算法

输入：`files[]`、`first_at`、`interval_min`、`account_id`

```
now  = 当前时间
plan = [first_at + i*interval_min for i in range(n)]
```

校验顺序（任一不过就返回错误，不落库）：

| # | 规则 | 级别 |
|---|---|---|
| 1 | `first_at >= now + 10min` | 硬拦 |
| 2 | `plan[-1] <= now + 7d` | 硬拦，提示拆批 |
| 3 | `interval_min >= 30` | 软护栏，开关可关，关时提示风险 |
| 4 | `n <= 15` | 软护栏，可改配置 |
| 5 | 同账号同日条数 > 5（带货）/10 | 黄色警告 |
| 6 | 计划时间与已有 job 冲突（同账号 ±10 分钟） | 警告 + 自动错开 10 分钟 |
| 7 | **同账号同日 ≥6 条同剧连续集** | 橙色警告（强提示，不拦）：「同一部剧一天连发多条，容易被判同质化搬运」 |
| 8 | 全部作业堆在同一账号同一天（间隔太小） | 提示「建议间隔 ≥2 小时，或跨天铺」 |

> 决策 5 确定「多个视频发同一个号」是主用法，那么**同一账号的连发强度**就是最大的风控变量。规则 3 的 30 分钟只是下限，不是建议值——UI 默认填 **120 分钟**，并把「同号同日条数」做成实时红黄绿灯，让用户在排期阶段就看见危险。


超 7 天的自动拆批：返回 `{"split": [[0..k], [k+1..n]]}`，前端展示「共 8 条，第一批 5 条到 11-16，第二批 3 条需 11-16 之后排」。

**预计上传耗时**：`sum(size) / 上行估算`。上行带宽无法可靠获取，用保守常数 1.5MB/s（12Mbps 上行），显示为「约 55 分钟（按 12Mbps 上行估算）」。

## 9. 自动化实现（app/wxchannel.py）

### 9.1 依赖与浏览器

- `playwright`（Python 包）。**不下载 Chromium**，用系统浏览器：`channel="msedge"` → 回退 `"chrome"` → 都没有则报错「请安装 Edge 或 Chrome」
- 每个账号一个 `user_data_dir`，`launch_persistent_context` 保持登录态
- 首次登录 `headless=False`（必须可见，用户扫码）；已 `online` 的账号可 `headless=True`

### 9.2 单条作业流程

```
open  channels.weixin.qq.com/platform/post/create
wait  上传控件就绪
JS    表单 frame 的 JS 上下文里 DataTransfer 造 File 塞 input（见「上传链验证」节；**不是** CDP）
wait  分片上传完成（出现「封面预览 / 编辑」；超时 20 分钟判失败）
      ※ 测试视频必须合规（有音轨、正常画面），黑屏无音轨会被前端静默拒绝
fill  标题 / 描述 / 话题 / 短标题 / 合集 / 原创声明 / 可见范围
pick  封面帧（若 cover_ts 给定，拖时间轴到该秒后点「设为封面」）
      ※ 若 cover_file 已指定则改为上传该图片；但 P1 不执行这步（通道已验证，产品化未开工，见封面图片变更节）
set   定时发布 → 选日期时间 → 确认
read  回「待发布」列表，按「标题 + 计划时间」匹配到本作业
done  status = scheduled, verified_at = now
```

### 9.3 选择器管理（这是唯一需要跟改版维护的地方）

全部集中在 `app/wxselectors.py` 的字典里，每项给三路兜底：

```python
SEL = {
  "file_input":   ["input[type=file]", "input[accept*='video']"],
  "title":        ["input[placeholder*='标题']", "textarea[placeholder*='标题']"],
  "desc":         ["textarea[placeholder*='描述']", "[contenteditable=true]"],
  "schedule":     ["text=定时发布", "text=定时"],
  ...
}
```

- 提供自检命令：`python -m app.wxchannel --selftest`，逐项输出命中情况（开发/售后排查用）
- 连续 3 次同一选择器不命中 → 立即停止该批次，**不当成单条失败继续跑**（避免整批空跑），并报「视频号后台页面可能已改版」

### 9.4 登录态

- 打开后台，URL 落到登录页 或 出现扫码区域 → `state = expired`
- 前端账号卡片变红，文案「账号『大彬的绳生』已掉线，需重新扫码」
- **绝不在 expired 状态下继续排下一批**，否则整批全废

### 9.5 多账号串行

- 全局单 worker，一次只处理一个 job，不并发上传（家用带宽 + 内存 + 风控）
- 切换账号时复用已开 context，超过 15 分钟未用则关闭释放内存

## 10. 降级 B（必须实现）

触发条件（任一）：
- 任意 Playwright 异常 / 超时
- 登录态 expired
- 选择器连续不命中
- 上传超时（20 分钟）
- 自动重试 2 次仍失败

动作：
1. `job.status = manual`，`job.error` 写入人话原因（例：「视频号后台没找到上传按钮，可能页面改版了」）
2. 桌面通知 + 前端队列里该行红色高亮
3. 该行出现三个按钮：**复制标题和话题** / **打开文件所在目录** / **打开视频号助手**
4. 用户发完点「已发」，点「跳过」需填一句原因

> 降级不是「失败了再说」，是产品的一部分：**只要 A 挂了，用户永远有一条 20 秒能走通的路**。

## 11. 界面规格

### 11.1 入口与形态

- 位置：`web/index.html` 顶部工具栏，按钮「发布计划」，带角标（待发条数）
- 形态：右侧抽屉（720px），不打断项目上下文；**不新增第 6 步**，避免污染 5 步主线
- 代码：新增 `web/publish.js`（独立模块），不塞进已 176KB 的 `app.js`

### 11.2 区块

**顺序按决策 5 固定为：先选视频 → 再选号 → 再排期。**（主用法是多个视频发同一个号；选号控件是单选，不做多选）

| 区块 | 内容 | 主视区文案（只写「点了会发生什么」） |
|---|---|---|
| ① 添加区 | 「从本项目成片选择」多选（**默认一条都不勾选**）+ 「从本机选视频」按钮 | 「选中后会自动带出标题和时长」 |
| ② 账号条 | 单选账号卡片（头像/名字/状态胶囊/重登·改名·删）+「添加账号（微信扫码）」；扫码面板会自己换码（4 分钟） | 「一批只发一个号，换号请新建一批」 |
| ③ 整批通用设置 | 合集 / 位置 / 活动 / 视频声明 / 扩展链接 / 话题 / 声明原创 + 「套用到这批视频」（见 §6.2.1） | 「整批一样才放这儿；标题和封面是每条各自的」 |
| ④ 排期区 | 首条时间 + 间隔（默认 120 分钟）+ 预览「共 N 条，最后一条 X」+ 同号同日红黄绿灯 | **P1：「到点提醒你，文案和文件都准备好」**（不能写「自动发」，P1 是人工点发布） |
| ⑤ 队列表格 | 集号徽章 / 可编辑标题 / 账号 / 计划时间 / 状态 / 「文案」展开（短标题·封面帧·话题）/ 操作 | 状态点 + 人话状态 |
| ⑥ 底部 | 开始排队 / 撤回排期 / 清空未排期的 | 「开始后可以关掉这个面板」 |

> **拖拽为什么改成按钮**：浏览器出于安全拿不到拖入文件的绝对路径（`File.path` 早已移除），
> 所以只能让后端弹系统选择框（`nativedlg.pick_files`，支持多选）。
> 拖拽看起来更顺，但落地只能是「假装接收了、其实拿不到路径」，不做假动作。

### 11.3 文案纪律（沿用现有铁律）

- 主视区**不出现**：Playwright / 选择器 / 浏览器自动化 / 转码 / CDP / profile / 模拟点击
- 原理与风险进 `<details class="fold">`：「它是怎么发的」+「什么情况下会失败」
- **例外**：pro 门禁提示必须出现在主视区（不然用户不知道为什么点不动），但只写「此功能需要专业版」，**不写价格、不写额度**
- 首次开启必须勾选风险确认（见 §13）

## 13. 合规与免责（面向客户，必须做）

1. **首次开启强制勾选**：「我已知晓：本功能通过模拟人工操作视频号后台完成发布，可能因平台规则调整而失效，极端情况下可能导致账号被限流。风险由使用者自行承担。」——落库到 `config.publish_risk_accepted = {at, version}`，改版本号需重新确认。
2. **产品文档明确写**：本功能不是微信官方接口，不保证持续可用；失效时请用降级手动流程。
3. **审计**：`audit` 新增动作 `hookcut.publish`（三处对齐：`app/audit.py` / `deploy/proxy/app.py` / `admin.html`），记录批次开始/结束/失败数。

### 13.4 功能门禁（决策 6：pro 专属）

现有 `LEVELS` 只管额度，不管功能。新增独立判据，**不复用额度入口**：

```python
# app/core.py
PUBLISH_LEVELS = ("pro", "internal")        # 唯一来源
def feature_allowed(level: str, name: str) -> bool: ...
```

- **服务端判**：`/publish/*` 所有写接口开头调 `feature_allowed`，不通过返回 403 `{"code":"NEED_PRO"}`。前端隐藏按钮只是体验，不能当门禁。
- **下发**：**不放在 `/api/status`**——那会让每次启动都多打一次服务端、拖慢首页。
  改成抽屉打开/轮询时随 `GET /api/projects/{id}/publish` 的 `gate` 字段一起返回，
  前端按 `gate.ok / gate.reason` 渲染（实现见 `publishapi.gate`）。
- **断网回退**：沿用现有「断网回退本地校验」的思路，用缓存的 `level` + 24h 有效期判断；过期按 `free` 处理（保守），并在界面提示「网络异常，功能暂不可用」，**不能误判成免费用户去提示升级**。
- **到期不打断**：见 §7——已排队列跑完，新增拒绝。
- `internal` 必须可用（自己和测试）。
- 文案纪律：升级提示可以出现在主视区（否则用户莫名其妙用不了），但**只写「需要专业版」，不写价格、不写次数**（沿用「次数与价格不进主视区」的铁律）。

### 13.5 自动生成的限流（决策 4：不扣额度）

不扣额度 = 成本在你这，必须防刷：

| 限制 | 值 | 位置 |
|---|---|---|
| 单批一次生成条数 | ≤ 20 | 服务端 |
| 单账号每分钟生成次数 | ≤ 5 | 服务端（内存滑动窗口） |
| 非 pro 用户 | 不开放 | 与 13.4 同一判据 |
| 单次失败 | 不计次、不阻断排期 | 标题留空让用户手填 |
| 单条 prompt 长度 | 截断到 1500 字台词 | 控 token |

**数据来源见 §13.6**（分层降级，不依赖任何非必做步骤）。

### 13.6 标题/话题的数据来源（修正：不许假定前置步骤跑过）

**前提**：发布的视频是**用户自己选的**，可能是本项目第 3 步成片、某集去字幕副本、甚至任意本地文件。所以任何自动填充都必须按「信息是否一定存在」**逐层降级**，不能假定某条处理链一定跑过，尤其**不许依赖第 4 步分镜**（可选步骤，很多项目不做）。

| 层级 | 数据源 | 可用条件 | 触发 | 成本 |
|---|---|---|---|---|
| **L1 模板拼接（默认）** | 项目名 / 文件名去扩展名 / `set.index`·`set.tag` 取集数 | 永远可用 | 自动，无需点按钮 | 0 |
| **L2 规则话题** | `#剧名` `#短剧` + 用户在模板区自定义 | 有剧名 | 自动 | 0 |
| **L3 智能生成** | 该集台词：**第 1 步转写 `ep.lines` 优先**；无转写则降级为「文件名 + 项目名」 | 点按钮才走 | 手动 | 模型 |

硬规则：
1. **L1 的值必须能直接当标题用**，用户不改也能发（例：`逃婚当天，我成了大佬的白月光-第3集`）
2. **来源优先级：项目名 > `set.tag` > 文件名**；文件名要剥掉扩展名与 `第X集-` 前缀再兜底
3. **外部文件（无项目上下文）**：只喂文件名，界面提示「这个视频没有项目信息，建议手填标题」，**不假装能生成**
4. L3 失败 → 标题留空并保留 L1 的值，不阻断排期
5. 每条都记录 `title_src`（`template` / `model` / `manual` / `filename`），出问题时能查是哪来的

## 15. 分期计划

| 阶段 | 内容 | 可独立验证 |
|---|---|---|
| **P1** | 账号管理（手动录入名称）+ 队列 + 排期算法 + 模板 + 界面 + **全部走 manual 状态** | 能排期、能看队列、能人工发并标记（不含自动化，零风险） |
| **P2** | 单账号自动化：上传 + 填表 + 设定时 + 回读校验 | 真账号跑通 1 条 |
| **P3** | 多账号 + 登录态管理 + 降级 B + 自检命令 | 3 个号各 2 条跑通 |
| **P4** | 标题/话题自动生成（走 `core.route()`，**不扣额度 + 限流**，见 §13.5） | 生成可用、限流生效即通过 |

P1 可以单独发布给客户用，即使 P2 出问题也不影响。

> pro 门禁（§13.4）在 **P1 就要落地**，不能等 P4。否则免费用户先拿到队列功能，后面再收回会挨骂。

## 16. 验收清单

- [ ] 首条时间设成 2 分钟后 → 被拦，提示最短 10 分钟
- [ ] 10 条 × 12 小时间隔 → 提示超 7 天并给出拆批建议
- [ ] 间隔设 5 分钟 → 软护栏触发，提示风险，允许强制开启
- [ ] 本项目 5 条成片勾选后，标题按模板自动带出，时长/大小正确
- [ ] **没做过第 4 步分镜的项目，标题照样有值（走 L1 模板），不为空**
- [ ] **拖入一个外部视频 → 标题只用文件名，且提示「建议手填标题」**
- [ ] **一条都不勾选时，开始排队按钮置灰，不能凭空发**
- [ ] **删项目时还有未发队列 → 弹窗给出「取消删除 / 仍然删除」，并写明平台侧定时不会撤销**
- [ ] 排期预览显示「共 N 条，最后一条 X，预计上传 55 分钟」
- [ ] **先选视频（多选）→ 再选 1 个号**，选号区只允许单选
- [ ] **批次已开始后改账号 → 置灰，提示「改号请新建批次」**
- [ ] **同号同日排 8 条 → 橙色警告「容易被判同质化」**
- [ ] **free 账号打开抽屉 → 显示「需要专业版」，写接口返回 403，不是只隐藏按钮**
- [ ] **断网且缓存过期 → 提示「网络异常」，不显示升级引导**
- [ ] **pro 到期时队列有 3 条 queued → 3 条跑完，新增被拒**
- [ ] 队列跑起来后关掉抽屉再打开，状态不丢
- [ ] 程序重启后，`uploading` 状态的作业回到 `queued`（不重复发布，靠 hash 去重）
- [ ] **关机过夜后打开 → `scheduled` 且已过时的条目补回读一次**
- [ ] **作业视频文件被删 → 标 failed，原因写「视频文件不见了」，不静默跳过**
- [ ] 拔网线 → 该条转 manual，红色行出现三个按钮，复制内容正确
- [ ] 删掉账号 profile 目录 → 检测后变 expired，且不会继续排下一批
- [ ] 同一条视频加两次 → 第二次被 hash 拦住
- [ ] 已托管条目过期后回读，查不到时显示「未确认」，不显示「已发布」
- [ ] 「停止」后当前条跑完即停，后续保持 queued
- [ ] 自动生成连点 6 次 → 第 6 次被限流拦下，提示稍后再试

## 17. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 视频号助手改版，选择器全失效 | 高（一年数次） | 所有客户同时失败 | 选择器集中 + 自检命令 + 失败即降级 B + 连续不命中即停批 |
| 客户账号被限流 | 中 | 客户投诉 | 风险确认书 + 日条数警告 + 单批上限 |
| 登录态 7~30 天过期 | 高 | 批次全废 | 每批开始前强制 check，expired 不排 |
| 上传慢被误判卡死 | 中 | 用户以为坏了 | 显示预计耗时 + 实时进度 + 单条 20 分钟超时 |
| 杀软拦截 | 中 | 装不上/跑不动 | 安装说明加白 + 启动失败给人话提示 |
| 多号同 IP 风控 | 中 | 限流 | 串行上传 + 默认最小间隔 30 分钟 |
| **同号连发同剧被判同质化**（决策 5 的主用法） | 中高 | 限流/降权 | 同日 ≥6 条橙色警告 + 默认间隔 120 分钟 + 建议跨天 |
| **不扣额度被刷模型** | 中 | 你的 API 账单 | 单批 ≤20、每分钟 ≤5、pro 限定、prompt 截断 |
| **pro 门禁与断网判错** | 中 | 正版用户被误判免费 | 24h 缓存 + 明确区分「断网」与「未开通」两类提示 |
| **项目删除后队列残留** | 低 | 平台侧还在待发布 | 删项目前检查 `publish.jobs` 未完成数并提示 |
