# 交付形态说明：为什么是一个 exe，又为什么它旁边有 6 个文件夹

## 1. 为什么是 exe，而不是一个网站

因为**转写和剪辑跑在用户自己的电脑上**。

| 环节 | 在哪跑 | 换成网页版会怎样 |
|---|---|---|
| 转写（Whisper small） | 本机 CPU | 一集 200-800MB 视频要传到服务器；服务器得配 GPU，成本按人头翻倍 |
| 切片 / 拼接 / 烧字幕（ffmpeg） | 本机 CPU | 同上，且每次改一个字都要重传 |
| AI 排结构 / 写分镜 | 服务器（只发台词文本，几百 KB） | 一样，已经是最省的形态 |

也就是说，界面是网页，**引擎在本地**。exe 干的事就是「把一个本机服务拉起来 + 打开浏览器」。
如果做成纯网页版，等于把一个视频剪辑软件塞进浏览器——上传、存储、算力三样全落在你身上。

另外两条现实原因：
- 《网络安全法》/备案下，纯网页版要处理内容审核、留存日志；本机工具不碰这些。
- 视频素材在用户硬盘上（`F:\剪影\<剧名>\`），网页版读不到本地盘。

## 2. 为什么旁边有 6 个文件夹（不能压成一个 exe 吗）

能压，但压了会变成「每次启动解压 900MB」。

| 目录 | 内容 | 大小 | 为什么要独立 |
|---|---|---|---|
| `钩子工坊.exe` | 启动器 | ~2 MB | 就是它 |
| `_internal/` | Python 运行时 + 全部依赖（FastAPI、faster-whisper、ctranslate2、onnxruntime） | ~430 MB | PyInstaller 的运行时目录 |
| `models/` | Whisper small 模型 | ~460 MB | 转写必须读文件，ctranslate2 不支持从内存加载 |
| `bin/` | ffmpeg.exe / ffprobe.exe | ~210 MB | 外部二进制，进程调用 |
| `web/` | 前端页面 | ~1 MB | 出事能直接改、不用重新打包 |
| `prompts/` | AI 提示词 | ~50 KB | 同上，改完刷新即生效 |
| `data/` | 配置/数据库/项目（运行时生成） | 0 起 | 数据必须可备份、可搬走 |

**为什么不用 PyInstaller `--onefile`**（把所有东西塞进一个 exe）：它在每次启动时把 900MB
解压到 `%TEMP%`，实测启动要 1-2 分钟、磁盘瞬时多占一份、杀软每次都全量扫一遍。
**这是唯一真正「一个文件」的做法，但用户体验比现在的文件夹差一个数量级。**

## 3. 现在的交付形态：一个安装器 exe

`钩子工坊-0.1.4-安装.exe`（单文件，550 MB）——双击后：

1. 解压到 `%LOCALAPPDATA%\HookStudio`（用户永远不用看见这个目录）
2. 桌面生成「钩子工坊」图标
3. 自动启动，浏览器打开界面

重装不丢数据：安装器会先把老的 `data/` 整个挪走，解压完再搬回来。
程序在跑时不让装，会提示先关掉。

**两个必须记住的坑（都实测踩过）**：

| 现象 | 根因 | 修法 |
|---|---|---|
| 装完「正在启动…」之后再无反应，端口起几秒就消失 | 安装器自己也是 PyInstaller 单文件，子进程继承 `_MEIPASS2`，误用安装器的临时解包目录；安装器退出后该目录被删，子程序跟着死 | 启动前剔除所有 `_MEI*` / `_PYI*` 环境变量，并置 `PYINSTALLER_RESET_ENVIRONMENT=1` |
| 用 `DETACHED_PROCESS` 启动，程序完全起不来 | 程序是控制台程序、靠那个黑窗口活着 | 用 `CREATE_NEW_CONSOLE` |

另外：中文控制台默认 GBK，安装器里要先 `chcp 65001` 再 print，否则用户看到的是乱码。

源码：`installer.py`；打包脚本 `build_installer.py`（同步说明书 → 压 payload → 打 exe）。

## 4. 发版流程

```bat
:: 1) 改版本号：app/buildstamp.py 的 VERSION（客户端自报版本）
::    同步 deploy/proxy/release.json 的 version（后台「版本发布」读的是它）
cmd /c build.bat                                    :: onedir 产物 → dist\HookStudio
runtime\Scripts\python.exe build_installer.py dist\HookStudio dist7 --force
```

**`--force` 不是可选项**：`build_installer.py` 发现 `build_tools/payload.7z` 已存在会直接跳过压缩，
新代码就进不了包（2026-11-05 实际踩过：安装器打完了，装出来还是旧版）。
另外 `build.bat` 会先删掉整个 `dist\`，等于把 data 也清空，`build_post.py` 会写全新的分发配置。

**输出目录每版换一个**（dist3=0.1.0 / dist4=0.1.1 / dist5=0.1.2 / dist6=0.1.3 / dist7=0.1.4 …），别覆盖上一版，
出问题还能拿旧包回滚。

打完把 `dist7\钩子工坊-安装.exe` 按版本重命名（如 `钩子工坊-0.1.4-安装.exe`）再发出去。

要发给别人的只有 `dist7\钩子工坊-<版本>-安装.exe` 一个文件。

**发布前防呆三查**（都在打包之后、发出去之前做）：

1. `build_tools\payload.7z` 里的 `data/config.json` 只能有 `dist_mode / report_audit / llm_model`，
   出现 `llm_key` / `jwt_secret` 一律不许发（`7z e -so build_tools/payload.7z data/config.json`）
2. 产物里的 `web/` `prompts/` 与源目录 md5 一致（`robocopy /MIR` 之外的手工改动常漏）
3. 双击 `dist\HookStudio\钩子工坊.exe` 起一次，`/api/status` 的 `version` 是新版号、
   `dist_mode` 为 true；起完之后**必须**重跑 `python build_post.py dist\HookStudio` 清掉
   这次启动写回的 `jwt_secret`（否则下次压缩就把密钥发出去）
