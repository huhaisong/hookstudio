# 钩子工坊 · 管理员手册

> 面向**发版的人 / 管理后台账号**。普通终端用户看 `docs/使用说明.txt` 就够了，
> 那份里不提 Key、不提模型——因为分发版里根本没有这些输入框。

## 1. 为什么普通用户不需要配 Key

分发版（`dist_mode=true`）里，AI 凭证只存在两处，都不在用户手里：

| 位置 | 内容 | 谁看得到 |
|---|---|---|
| 服务器 `/opt/hsproxy/.env` | 百炼 Key（`DASHSCOPE_KEY`） | 只有你，SSH 进去 |
| 服务器 `/opt/hsproxy/data.sqlite` | 账号 / 会话 / 每账号每日用量 | 只有你，`/admin/stats` |

客户端流程：登录 → 领一张 15 分钟票据（绑人 + 绑项目 + 绑用途）→ 本机后端带票据调
`/api/proxy/chat/completions` → 服务器用它的 Key 转发给百炼。**Key 永远不下发**。

所以「用户自己填 Key」是**老版本**的做法，已经废弃；`使用说明.txt` 里任何让你填 Key 的
段落都是过时文案。终端用户的设置页里，这两栏是直接 `display:none` 的，接口层也 403。

## 2. 运营后台（2026-11-04 上线）

**网址：<https://api.hookstudio.cn/admin>**，输入管理密钥（`deploy/.env.admin` 里的那串，
= 服务器 `/opt/hsproxy/.env` 的 `ADMIN_KEY`）即可进入。密钥只存浏览器 sessionStorage，
关掉标签页即失效。

五个页签：

| 页签 | 能干什么 |
|---|---|
| 概览 | 今日活跃账号 / 今日调用 / 24h 调用与 token 消耗 / 账号总数；近 14 天用量柱图；最近 50 次调用明细 |
| 用户账号 | **账号在这里**（账号存服务器，本机只留断网登录用的镜像）：谁注册了、今天用了几次、绑在哪台电脑、最后登录时间与 IP；`+10` 补次数、`解绑`（换电脑用）、`封禁/解封`（封禁后他的所有会话立刻失效、登录被拒并看到理由）、`改密`、`备注` |
| 客户端日志 | **上半屏「操作统计」**：按动作聚合的次数 / 用户数 / 设备数 / 失败数（近 24h / 7 / 30 / 90 天）——登录、生成结构、生成分镜、改提示词、AI 调用一目了然；没有专门埋点的操作（如新增项目）看「高频接口」表。**下半屏「流水」**：逐条日志，可按设备 / 动作 / 关键字 / 只看失败筛选，点行展开详情 |
| 系统日志 | **服务端自己**的日志（2026-11-05 加）：未捕获异常（500）带完整堆栈、启停记录、慢请求、上游 402/429/401、后台管理操作审计。分不清「用户用错了」还是「我们服务坏了」时看这里 |
| 版本发布 | 改「最新版本 / 下载地址 / 更新说明」；**最低可用版本填了就会拦住旧版客户端**（保存时有二次确认），日常发版留空 |

页面本身不含数据，所有数据接口仍然要求 `X-Admin-Key`；`deploy.py` 会自动上传
`proxy/admin.html` 并自测 `/admin` 返回 200。

### 2a. 系统日志（2026-11-05 加）

客户端日志回答「用户机器上发生了什么」，系统日志回答「服务器自己怎么了」。
在这之前服务端是**全静默**的：访问日志被关掉、500 只把异常类型名回给客户端、
堆栈当场丢弃 —— 线上炸一个接口等于无痕，只能靠用户截图猜。

| 卡片 | 内容 |
|---|---|
| 近 7 天错误柱图 | 每天的服务端异常条数（北京时间切天），没有柱子 = 0 |
| 服务端错误 | 时间 / 接口 / 异常类型 / 状态 / IP / 说明，**点一行展开完整堆栈**；可按接口、异常名、IP 搜 |
| 运行事件 | `boot` 启停、`slow` 慢请求（默认 ≥1000ms）、`upstream` 上游 402/429/401、`http` 主动抛的 5xx、`admin` 后台操作（封禁/解封/踢下线/解绑/补次数/重置密码/改备注/改发版配置/管理员密钥错误） |

- 数据在 `server_error` / `server_event` 两张表，**保留 30 天**（每小时自动清理）。
  调保留期和慢请求阈值：服务器 `/opt/hsproxy/.env` 加 `LOG_KEEP_DAYS` / `SLOW_MS`，重启生效。
- 管理员密钥被撞只记「同一 IP 半小时一条」，避免公网扫描器把日志刷成噪音。
- 只记「慢」和「错」，不记全量访问日志 —— 0.5G 小机器上全量会把 journal 撑爆，
  真要看请求量用「概览」的调用统计。
- 排查顺序建议：先看系统日志有没有 `upstream` / `http.5xx`（我们的问题），
  没有再去客户端日志看具体用户的操作（用户的问题）。

## 2b. 账号体系（2026-11-04 起账号在服务器）

**为什么搬**：本机账号是每台电脑各自一份，A 电脑注册的 B 电脑不存在；而且「第一个
注册的人自动当管理员」，等于每个用户在自己机器上都是管理员——运营看不到是谁在用，
封禁也封不住（重装换个设备令牌就是新身份）。

现在的规则：

- **注册 / 登录走服务器**（`/api/auth/register` / `login`），客户端本地只留一份镜像
  （密码哈希存本机，用于**断网登录**——没网照样剪片，只是调不了 AI）。
- **一个账号默认绑一台电脑**（首次登录时记录）。换电脑登录被拒，后台「解绑」后可换。
- **额度按账号算**（`account_daily` 表）。**设备令牌轨道已整体删除**（2026-11-05：
  测试期无老客户，`tokens`/`daily_usage` 表、`/admin/tokens`、`/admin/grant` 接口
  全部下线，老客户端连不上新接口会直接要求重新登录——不存在兼容通道）。
- **封禁三连**：账号标记 banned + 删除全部会话（所有设备立即下线）+ token_version+1；
  客户端登录时收到 403 会顺手把本地镜像也标成 banned——**拔网线也绕不过去**。
- **没有老用户迁移**（2026-11-05 定稿）：只在本地存在的账号登录直接 401，
  不会「本地密码对就自动注册到服务器」。测试期无老客户，删掉岔路系统更简单、
  也没有免费通道漏洞。
- **没有管理员角色**：终端账号只有一个身份（user），管理权只在运营后台。
- 密码规则与客户端一致（≥8 位、非纯数字、防弱口令），PBKDF2-HMAC-SHA256 26 万轮。
- 注册限流：同一 IP 每小时最多 5 个账号（`REG_PER_IP_HOUR`），防「换号白嫖每日次数」。

客户端改动涉及：`app/remote.py`（新增，服务器通信唯一出口）、`app/auth.py`
（register/login/change_password/logout 接服务器）、`app/core.py`
（`account_token` / `ai_token`，修了 device_token 从不落盘的老 bug——见下）、
`app/analyze.py`（AI 请求优先带账号令牌）、`web/auth.html`（注册文案，删掉
「第一个用户是管理员」和 admin123456 提示）。

## 3. 每天 10 次额度

- 规则：**每个账号**每天 `FREE_CALLS_PER_DAY`（默认 10）次，**北京时间 0 点重置**。
  （服务器在香港，系统时区是 UTC；用 UTC 切天会让用户在晚上 8 点跨天，所以代码里
  固定 `DAY_TZ_OFFSET=8h`。）
- 计费：只有**上游真跑成功**才扣；失败、超时、票据失效都不扣。转写/切片/出片/
  两两合并不扣。
- 改阈值：服务器 `/opt/hsproxy/.env` 改 `FREE_CALLS_PER_DAY=30`，`systemctl restart hsproxy`。
  不用重新部署代码。
- 给某人补次数：后台「用户账号」页签点 `+10`，或
  `POST /admin/account {"id": <账号id>, "action": "grant", "add": 5}`，
  **只补当天**，跨天清零（按天计费后「加一辈子额度」已无意义）。
- IP 限流：AI 调用 `IP_LIMIT_HOUR` / `IP_LIMIT_DAY`（默认 30 / 200），
  注册另有 `REG_PER_IP_HOUR=5`。取的是 `X-Forwarded-For`
  第一段（caddy 会覆盖伪造值，实测过）。

## 4. 模型怎么选（2026-11-04 实测 13 个）

详见 `docs/模型对比报告.html`。结论：

| 场景 | 推荐 | 实测 |
|---|---|---|
| 排结构（第 2 步，21.7 分钟剧出 3 套） | `ZHIPU/GLM-5.2` | 59 秒、时长最准、重合 72%（需在百炼「模型广场」开通智谱） |
| 不想额外开通 | `qwen3.5-plus` | 3.5 分钟、重合 70%，默认值 |
| 只要最低重合 | `qwen3.8-max` | 57%，但要 19 分钟 |
| 只出一套 | `deepseek-v4-pro` | 快，但三套重合 100% |
| 写分镜（第 3 步） | `qwen3.8-max` | 一次过、无警告 |

**两步可以各配一个模型**：设置页「分镜模型」栏，留空 = 跟主模型一致。
链路 `shots_model` → `core.route()` → 同一个降级阶梯。

**推理型模型的思考开关**：GLM-5.x / MiniMax / step-5 / DeepSeek V4 会把思考算进
`completion_tokens`，16k 能被吃光、正文为空。程序会按 `_is_thinker()` 先带
`enable_thinking=false`，400 就退 `reasoning_effort=low` + 32k，再 400 摘参数。
GLM-5.3 明确不支持关闭思考，只认 `reasoning_effort`。

## 5. 双 Key 路由（别改回按前缀判断）

`core.route(model, llm_key, ds_key)` 只认**白名单**：

- `DEEPSEEK_OFFICIAL = (deepseek-v4-pro, deepseek-flash)` 且 `ds_key` 非空 → DeepSeek 官方
  （`https://api.deepseek.com/v1`）
- 其余一律走百炼

**绝不能按 `deepseek` 前缀判断**：百炼也上架了 `deepseek-v4.1-flash`，按前缀会送错接口 → 400。
DeepSeek 官方现在只有 `deepseek-v4-pro`、`deepseek-flash`；老名字 `deepseek-chat/reasoner`
会 404。

## 6. 测试连通

设置页「测试连通」→ `POST /api/llm-test`，探针与正式调用共用 `core.route()`，
两个模型（主模型 / 分镜模型）各测一次。报错已翻成人话：

| 原始错误 | 界面提示 | 处理 |
|---|---|---|
| `Arrearage` | 账号欠费 | 百炼控制台充值，Key 不用换 |
| `token is unusable` / `Access denied` | 模型没开通 | 「模型广场」逐个申请 |
| `invalid_api_key` | Key 失效 | 换 Key |
| `Throttling` | 被限流 | 隔一会儿再试 |
| `requests.Timeout` | 超时 | 20 分钟后重试；确实慢就换模型 |

**遇到超慢先重试一次再换模型**：qwen3.5-plus 单次复核撞过 900s 超时，20 分钟后重试 221s 就过，
是百炼排队拥堵。

## 7. 发版前必做

0. 改版本号：`app/buildstamp.py` 的 `VERSION`（客户端自报的版本）+ `deploy/proxy/release.json`
   的 `version`（后台「版本发布」显示、客户端比对的就是它），两处必须一致
1. `cmd //c build.bat`（onedir 打包到 `dist\HookStudio`；**--noupx 不是可选项**——
   UPX 压 onnxruntime 的 .pyd 有已知解压崩溃；打包前清掉 dist 里旧的 data/，
   build_post.py 会写全新的分发配置）
2. 打单文件安装器：
   `runtime\Scripts\python.exe build_installer.py dist\HookStudio dist7 --force`
   → 产出 `dist7\钩子工坊-安装.exe`，按版本改名成 `钩子工坊-0.1.4-安装.exe` 再发
   （**`--force` 必带**：payload.7z 已存在时脚本会跳过压缩，新代码进不了包；
   输出目录每版换一个：dist3=0.1.0 / dist4=0.1.1 / dist5=0.1.2 / dist6=0.1.3 / dist7=0.1.4，别覆盖上一版）
   它会把 docs/使用说明.txt 同步进包。
   要发 zip 测试包必须走 `pack_zip.py`——它会先重置分发配置再压；
   **验证 exe 后绝不能直接压缩目录**（启动一次就会把带 jwt_secret 的
   config 写回 data/，压进去等于把签名密钥发给所有用户）。
3. 部署服务端：`runtime\Scripts\python.exe deploy\deploy.py`（会上传 app.py / admin.html /
   release.json 并 restart 服务；只改 `min_supported` 推强制更新时不用重新部署）
4. 推强制更新：后台「版本发布」页签改「最低可用版本」，或直接改服务器
   `/opt/hsproxy/release.json`，**不用重新部署**
5. 交付形态：见 `docs/交付形态说明.md`（一个 exe 安装器 vs 解压目录）
