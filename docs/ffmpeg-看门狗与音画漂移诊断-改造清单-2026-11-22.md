## 〇、现状盘点结论(2026-11-22 实测)

**已经有、不用再做的:**

| 能力 | 现状 | 位置 |
|---|---|---|
| 可中止子进程基建 | `run_cancelable`/`wait_cancelable`/`register_proc`/`_kill_procs`,管道排空、按任务组批杀 | `core.py:1417-1518` |
| ffmpeg 调用收敛 | `render._run` 已覆盖 render.py 全部 13 处;`_run_v`(GPU 感知)覆盖 4 处,vmerge.py:134 也走它 | `render.py:2184/892` |
| 机器进度 | `-progress pipe:1 -nostats` 已接入:direct 路径解析 frame,nosub 解析 out_time_ms | `render.py:2196`、`nosub.py:262` |
| GPU 中途失败回退 | 整段退软编重试一次 + 硬件开关永久关(「宁慢勿败」),比零界的盲目重试更严 | `render.py:763-778` 注释④、`_run_v` |
| 防漂移构造 | 同帧率钉死解码/编码端;变速 setpts+atempo 同步、时长钉整数帧;apad/atrim 钉音轨;等长静音防累积 | `nosubfill.py:70`、`render.py:1747-1752/1818/2325/2364` |
| 静态超时 | 探测 30s(`render.py:800`)、音频解码 120s(`audiofp.py:93`)、短命令均有 | 各处 |

**缺的(本清单要补的):**

| 缺口 | 后果 |
|---|---|
| 活性看门狗 | ffmpeg 卡死(NVENC 驱动挂起等)只能等静态超时或永远挂着;无 timeout 的调用(run_cancelable 默认)无限等。运维记录里僵尸进程是真实踩过的坑 |
| 音画漂移检测 | 构造上防住了已知漂移源,但成片**没有验收环节**,若有未知漂移源(如某显卡驱动+某滤镜组合),坏片会直接发给用户 |
| ffprobe 并发控制 | 10 个文件直接调 ffprobe,批量 3 并发时无锁 |
| voiceiso 中止盲区 | `voiceiso.py:226` 的 Popen 未 register_proc,点「中止」杀不到它 |

## 二、R1 core 层原语(约半天,不碰任何调用方)

| # | 改动 | 细节 | 验证 |
|---|---|---|---|
| R1.1 | `core._drain_pipe` 改持续读 | 现在是一次 `read()` 到 EOF(`core.py:1438`),中途拿不到「有没有新输出」。改成循环 `read(4096)`/readline,记录 `last_output_ts`(time.monotonic)。签名/返回语义不变 | 假 ffmpeg 睡眠 90s,活性时间戳在推进 |
| R1.2 | `run_cancelable`/`wait_cancelable` 加可选参数 | `stall_sec: float = 0`(0=关,完全旧行为)、`out_path: str \| None = None`(输出文件观测路径)。等待循环每 0.25s 查中止(现状)+每 1s 采活性:管道有新字节 / out_path 的 st_size 或 st_mtime_ns 变化,任一命中刷新 last_activity | 参数缺省时逐字节对齐旧行为 |
| R1.3 | 熔断动作 | 杀进程(现有 proc.kill 路径)+ 抛 `StallDetected(RuntimeError)`,人话文案:「编码卡住 N 秒没有进展,已终止并重试」;诊断行 `[STALL] silent_for= output_size= cmd=<截120字符>` 进日志(对齐脱敏习惯) | 触发后进程树无残留、日志可 grep |
| R1.4 | `render._run`/`_run_v` 透传 | `_run_v` 内做 R0.2 的「熔断→原参数重试一次」;重试也 stall → 走既有 `_run_failure` 失败链 | direct 路径与 AI 路径行为一致 |

**红线**:中止(`TaskCancelled`)优先级永远高于 stall 熔断——`wait_cancelable` 现有「结束前再 check_cancel 一次」的顺序不能动(`core.py:1462-1466` 注释是实测教训)。

## 四、R3 音画漂移诊断(约半天)

| # | 改动 | 细节 |
|---|---|---|
| R3.1 | 新增 `probe_stream_duration(file, "v"\|"a")` | ffprobe `-select_streams v:0/a:0 -show_entries stream=duration -of default=noprint_wrappers=1:nokey=1`,超时 15s;**模块级锁**(批量 3 并发 × 多处 ffprobe,加锁防挤;实现放 core,风格对齐 `from . import core, render`) |
| R3.2 | 分级 | `drift = v_dur − a_dur`:≤0.1s ✅ 正常 / ≤0.5s ⚠️ 只记不拦 / >0.5s ❌。0.1s 容忍带吸收 mp4 容器层结尾 padding 噪音(钩子成片被 apad/atrim 钉过,容器级零点几秒差是正常的,不能当异常) |
| R3.3 | 检查点(防滥测) | 只测四处:**① 有变速/缓冲加速的段**(漂移高危)渲完测;**② 成片 concat 完**测;**③ vmerge 每对合并完**测;**④ nosub 抹字幕整集完**测(整集重编码)。**不逐段全测**——20 段 × 2 次 ffprobe 要 40-80s,白拖 |
| R3.4 | ❌ 处置 | 段级:按 R0.3 原参数重渲一次,仍 ❌ 整套标失败(人话:「第 12 段音画差 0.7 秒」);成片级/nosub 级:任务摘要标红 + 日志,不自动动片 |
| R3.5 | 断点语义 | 重渲计入该段的既有重试语义,**不新增 task.json 标记**,断点续跑判据不受影响 |
| R3.6 | UI | 诊断结果进现有任务日志与摘要;⚠️ 不打扰用户,❌ 才标红 |
